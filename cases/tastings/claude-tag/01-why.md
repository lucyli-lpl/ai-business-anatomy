title: 为什么是现在、为什么是 Anthropic
---

## 公司定位与产品前史

Anthropic 作为安全导向的 AI 实验室，走到了模型能力（Opus 4.8）与基础设施（MCP 生态）同时成熟的节点，使 agent 产品成为可能。

Claude in Slack 是前身——但它的问题不是功能不够，而是范式错了：**在多人世界里做单人机器人**。Claude Tag 不是迭代，是推翻重来。

## 演化路径

CLI → Slack-triggered Code → 内部共享 agent → 公开 Claude Tag。

关键洞察：Anthropic 不是先设计产品再验证，而是**通过内部使用发现了产品形态**，然后再产品化。这是"dogfooding 驱动的产品发现"。

## 三重使能条件

三个条件必须同时就绪：

- **模型**：Opus 4.8 的可靠性达到了可以在无人监督下执行任务的水平
- **基础设施**：MCP 生态提供了工具调用的标准化层
- **商业**：企业营收压力 + IPO 路径要求从 API 走向产品

## 核心架构决策

**"One Claude per channel"——不是 per user。**

这一个决策级联出了整个产品形态：共享记忆（channel 级而非用户级）、agent 身份（它是这个频道的成员）、公开可见性（所有人看到它的工作）、以及"同事"隐喻的自然成立。
